## Free archive continuity bug fixed in this PR

The **append-only archive writer** runs only when D1 discretionary research gate admits it; when Free D1 is over cap it cannot refresh `latest.json` at all. Its own `shouldUpdateSnapshots` logic also only writes a new rolling 72-hour view on new signals/seed, even if old signals naturally expired in place. As a result, static `latest.json` can keep an expired/unverified OSINT observation: website health correctly red-flags it. No new current headlines may be fabricated to fix that.

The **independent existing static archive deploy** now has a three-hour **no-D1 schedule**, regenerates `latest.json` from the exact historical immutable shards and the current wall clock, then reads only the existing public archive endpoint once to compare its **source-neutral signal rows and policy fields**. It skips an identical deployment; any missing/corrupt/expired/rights-different deployed rows force a bounded redeploy. It never rewrites original timestamps, old immutable archive shards, D1/B2/R2/KV, billing or PREDGE. Push/manual deployment remains available and does not skip. The 72-hour validity is independently verified from shard data. This can restore truthful **no recent original** status; it cannot generate missing macro/minerals publisher events.
