# India quarterly reporting-FX country digest

Explicit query: `{"fulfillment_mode":"published_only","delivery_tier":"structural_baseline","topics":["fx_external_risk"],"subjects":[{"type":"country","country_iso3":"IND"}],"detail":"compact"}`.

The existing canonical query engine can derive one India country module from the Fiscal Service quarterly reporting rate, at the unchanged structural-country-digest catalog price of 0.02 USDC. It is not a spot FX quote, a broad macro profile, current news, GRI input, signed GRO or evidence of completed settlement. Other countries/topics and signed-intelligence plans do not acquire this fallback.

The qualifier reads the official API terms and checks the exact reviewed response-byte SHA-256 before fetching numerical records. The published terms permit analysis services; the assessment is scoped to that permission, excludes logos/images/third-party prose, and makes no government endorsement claim. `CERTIFIED` here denotes this scoped technical source/permission check, not a signature by an independent facts/rights reviewer. An HTML revision must be reviewed and re-pinned, not silently accepted. The source hash and exact permission-document hash remain private provenance.

Two consecutive completed calendar quarters, exact India/Rupee identities, matching effective/reference dates and strictly positive fixed-point rates are required. The latest quarter must be no older than 125 days. Amendments with differing effective dates, duplicates, missing prior quarters, future/stale dates, HTTP failures, redirects and oversized bodies fail closed. Percent change uses six-decimal fixed-point arithmetic with half-even rounding. Quarter-end reference time is never a publication or retrieval timestamp. Retrieval is cached in memory for five minutes; failures back off for one minute. No new persistent database is used.

Run `bun scripts/ops/prepare-treasury-country-digest.ts` with Supabase in standby to verify real source/terms acquisition, canonical deliverability, canonical response and exact customer-byte hash. The no-secret workflow runs this after offline regression checks. Only a sanitized receipt is retained; no source/customer bytes or authority keys are uploaded to Actions artifacts.

This does not expand the old MCS-only private candidate-vault admission. That vault intentionally rejects Treasury candidates. A successful source/response receipt is not proof of deployed production parity, immutable remote freeze/readback, provider acceptance or customer entitlement. Those must pass through the existing commerce acceptance path before a paid offer is called launch-ready. No funds, paid API, Supabase reactivation, key creation or independent approval is part of this change. Original signed-product deep health remains independent and may remain unavailable.
