## Scientific and commercial boundaries

Only eight pinned official GOV.UK Atom sources across Geopolitics,
Macro/FX and Critical Minerals are actively queried. The source adapter
uses <updated> only as a discovery hint. The exact first-party original
article HTML and the publisher Content API first_published_at must
agree with the article title, path and precise original publication
clock before a country research event is admitted. Exact single-country
headline attribution is a preliminary event-location hint, not proof of
an incident or cross-publisher corroboration.

Low provisional severity <40 is skipped. For admitted events the existing
PostgreSQL research RPC performs atomic evidence-hash deduplication and
country state update. Severity >=70 triggers a research-only Ed25519
signature, then independent Supabase durable readback verifies the
version, canonical SHA256 and signature. No evidence or real live event
means no dummy row, no fake signed GRO. First real event end-to-end
signed readback has NOT yet been proven by a live production observation.

This is not a universal 195x3 source guarantee, not verified sanctions
law, and not a paid or executable Risk Gate. The live source monitoring
and private fail-closed API are active; country intelligence coverage
requires genuinely observed verified events. Source rights are limited
to applicable first-party official metadata and excluded third-party
articles, not inferred from a feed being free.

## Operator-only Supabase SQL checks

Use the project's authenticated SQL Editor, not the public website.

    select jobid,jobname,schedule,active from cron.job
     where jobname like 'geomacro-research-stream20m%';

    select started_at,status,source_http_healthy,candidate_count,
     original_pages_verified,state_updated,signed_verified,failures
    from public.gm_research_stream20m_runs
    order by started_at desc limit 20;

    select count(*) as state_rows,
      count(*) filter (where signed_snapshot is not null
         and signed_version=version) as signed_current
    from public.country_risk_state;

For a **server-side** private client, the read token may be retrieved
in the owner's authenticated Supabase SQL Editor with:

    select decrypted_secret from vault.decrypted_secrets
    where name='gm_research_stream20m_read_token_v1';

Do not paste this result into chat, public JavaScript, GitHub, screenshots,
logging, or source artifacts. Never retrieve or expose the signing private
key or cron service token.

Example owner-server request (GM_RESEARCH_READ_TOKEN must be in the
server's private environment):

    curl -i 'https://ymjuwuvbialsevfawvvq.supabase.co/functions/v1/gm-research-risk-gate' \
     -H "Authorization: Bearer $GM_RESEARCH_READ_TOKEN" \
     -H 'Content-Type: application/json' \

hard kill switch. A separately provisioned legacy server-side profile
(ENABLE=1 with full private credentials) retains the old local verified
read implementation. Invalid native Edge responses, redirections and
commercial/execution claims fail closed. No public token disclosure.
