# GeoMacro P0-B durable B2 spool — production acceptance

## Code and migration
- Canonical source: PR #3497; migration \`workers/control-plane/migrations/0114_p0_b_spool_queue.sql\`.
- Source of truth for deployed Wrangler config: \`workers/control-plane/wrangler.example.jsonc\` -> \`wrangler.runtime.jsonc\` generated by \`deploy-d1-control-plane.yml\` (this repository uses JSONC, not an active \`wrangler.toml\`).
- When disabled, the deployment script removes new Queue bindings so legacy releases are unaffected.
- New Queue: \`geomacro-ingestion-spool\`. DLQ: \`geomacro-ingestion-dead-letter\`.
- B2 key prefix: \`spool/YYYYMMDD/{source_id}/{sha256}.json\`; cipher: AES-256-GCM with SHA-256/plaintext-AAD identity and exact ciphertext GET-hash verification.
- Cloudflare/B2 credentials are secrets only, never committed.

## Owner-scoped activation inputs
- GitHub production variable \`GEOMACRO_P0B_ENABLE=1\` and \`GEOMACRO_P0B_B2_SPOOL_BUCKET\` (a PRIVATE bucket in the current B2 S3 region).
- GitHub production secrets: \`GEOMACRO_P0B_B2_KEY_ID\`, \`GEOMACRO_P0B_B2_APPLICATION_KEY\`, \`GEOMACRO_P0B_SPOOL_ENCRYPTION_KEY\` (random 32+ character independent secret).
- Existing GitHub production Cloudflare deployment credentials and the existing PREDGE protected credential remain required. Never paste keys into chat.
- The canonical deploy workflow validates inputs, creates both Queues if missing, applies D1 migrations, deploys the Worker and installs Worker secrets. A new deployment with no explicit activation remains safe and does **not** simulate P0-B acceptance.
- Existing P0-A \`source_registry\` entries must be present in D1; an empty source registry produces no candidates. 0113 and 0114 require real remote migration readback.

## Required remote acceptance
1. Verify migrated tables \`source_registry\`, \`ingestion_spool_queue\`, and \`normalized_articles\` and required indexes in the remote D1 \`sqlite_master\`.
2. Confirm current Worker SHA equals canonical main and \`GEOMACRO_P0B_ADMISSION_ACTIVE=1\` in protected runtime configuration.
3. Confirm an eligible, real registered source is fetched. Check remote B2 object via exact GET/hash and authenticated decrypt; do not accept mock or placeholder.
4. Check the *same real candidate SHA* in remote D1: \`PENDING -> PROCESSING -> D1_COMMITTED\`, \`d1_committed_at\`, \`acked_at\` and one \`normalized_articles\` metadata row.
5. Verify Queue delivery only ACKs after independent D1 readback. Simulate a consumer interruption and verify redelivery, no duplicate D1 insert.
6. Check ten-minute drain, stalled visibility locks, dead-letter payloads, D1 quota and B2 account ledger tickets.
7. Verify the source cursor did not advance after incomplete B2 spooling; verify existing paid/partner/website contracts unchanged.

## Scope and throughput constraints
- All code/test acceptance can pass offline without proving live B2 capacity or 24/7 global ingestion. Do not report 100% live from test fixtures.
- The current shared B2 quota ledger explicitly caps the whole account at **720 requests/day** (GET 340, PUT 380). One new item normally requires a B2 PUT, a B2 producer verification GET, and a B2 consumer restore GET. 250 newly spooled+committed items require 750 B2 requests, beyond that existing ledger before accounting for other workflows. This needs separate quota policy acceptance; do not silently bypass it.
- Cloudflare Queues Workers Free includes **10,000 operations/day**. Single-message-per-candidate delivery normally uses 3 operations per accepted candidate; 6,528 items/day alone would require approximately 19,584 Queue operations/day before retries. Neither this architecture nor the Free-tier provider guarantees unlimited volume or zero external-source loss during provider outages.
- The FIFO drain's \`90,000 committed_today\` threshold is an explicit *queue admission-record* ceiling, NOT an account-wide D1 rows-written measurement. Production D1 Free row-write consumption must also be independently verified.
- The B2 stored objects are retained after ACK; lifecycle deletion/archival requires separate proof that raw evidence and retention obligations are preserved.

## Test command
\`npm run test:p0-b\` executes the six mandated offline acceptance cases plus queue-send failure recovery.
