# Geomacro independent multi-source event qualification — commercial boundary

**Status:** enforced at the source-aware intelligence D1 hot publisher, with separate server-side D1 metadata rejection. **Not a claim of 195+ × 3 current live coverage, not a payment launch approval.**

This is a verifiable internal qualification policy, inspired by industry-style multi-source corroboration (not a reproduction of Dataminr's proprietary detection methods):

```
New signal (PRIVATE) → genuine first-party original publisher URL/date → event identity (category, country, actor, target, location, event type, occurred_at) → independently authored confirmation by ≥2 registered originating organizations → independent item/content/reviewer hashes → source-specific derived commercial-use rights approval → trusted Ed25519 reviewer signature → canonical severity assessment → private qualification receipt digest → verified B2 readback + D1 current snapshot → independent product/x402 no-funds acceptance → explicit owner real-money ACK → payment
```

### Rules, non-negotiable

1. **Same event, not same words.** Require an EXACT structured event claim (event type, country ISO3, canonical actor/target/location and original event clock), with a SHA-256 digest matching every article's claim receipt. Two generic keyword headlines, different actions, different countries, or a search index do NOT establish independent corroboration.
1a. **Category–event consistency and real geographic membership.** A reviewer-signed event must use a domain-compatible canonical event type (e.g., `central_bank_policy` is Macro/FX, never Critical Minerals) AND its uppercase ISO3 must be a member of the project's authoritative 250-entity geography classification (194 sovereign, 53 territory, 3 special entities). A three-letter guess such as `ZZZ`, or a fabricated identity, fails admission before B2/D1. The publisher reads this versioned repository classification without external lookups or database writes; missing/drifted source fails closed. This does not verify that the underlying event truly occurred in that country—independently signed source/article nexus remains mandatory downstream.

2. **Two actually independent first-party reporting organizations.** Require at least two distinct *registered* originating institutions and original publisher hosts, separately validated first-party native published timestamps, distinct original article content hashes and independent reviewer receipts. A repost, syndicated wire copied across domains, second feed from the same institution, alias, GDELT first-seen time, or single RSS item never qualifies. Zero first-party evidence remains RED.
3. **Freshness.** Article publication must be genuine, at most six hours old and not in the future; independent original publications must be within 90 minutes of each other. The event clock cannot be manufactured from poll time or a feed `updated` timestamp. A quiet source never implies zero global risk.
4. **Commercial derived rights.** Both source-specific rights receipts must be positively verified internally. Open RSS or free access is NOT an unrestricted licence. Raw content is always private. Re-use of independently licensed/derived facts and customer-facing transformation must meet applicable legal rights.
5. **Trusted editorial proof.** The complete reviewed private evidence package must be Ed25519-signed with an independently configured trusted review public key (`GEOMACRO_INDEPENDENT_REVIEW_PUBLIC_KEY_PEM`). Arbitrary labels such as `independently_corroborated:true` are not sufficient. No trusted key or invalid signature means RED. The key must come from the authorized production reviewer, not arbitrary third-party text or user input.
6. **No raw customer outputs.** The result is a metadata-only receipt SHA-256, event IDs/domain/count and proof statuses. Article body, original headline, original publisher URL, private source provenance and rights documents remain behind internal governance. Public `live_observed` rows are suppressed until a separately approved signed, independently corroborated scored publication path exists. Historical signed objects remain governed by their own trust and staleness flags.
7. **No bypass by using only the publisher client.** The authenticated Cloudflare D1 control plane also rejects Intelligence PUTs lacking a recent multi-source receipt SHA-256/qualified count and refuses unscored `live_observed` row promotion. The control-plane metadata check is **defense in depth only**: the authoritative detailed signature/source verification happens in the trusted publisher before D1. Direct B2 object bytes by themselves are not public/paid availability.

### Source security and launch dependencies

- Current publisher registry has pinned authorities for UN News, UK FCDO, UN Geneva, Federal Reserve, ECB, USGS, NRCan Canada and Statistics Canada. Other global sources require separately verified registry expansion and legal review; identity claims are not accepted just because someone wrote an organization string.
- Hashes and signatures bind attested evidence but do **not** magically prove real-world publication or source rights if the trusted reviewer has not actually checked the original article bytes and licence. Upstream native original fetch, licensing, independent human/agent factual verification and downstream signed GRO still have separate acceptance.
- **Production is expected RED** until two qualifying originals for an actual same event, real content/rights/reviewer attestations, a configured authorized Ed25519 review public key, canonical scoring, private verified B2 readback and independent D1 hot product acceptance are available. Fake test fixtures and old timestamps are never production news.
- Current x402 remains no-charge/no settlement while `/api/health?deep=1` returns 503 or availability rejects current coverage. Pricing and mainnet activation are **not** implied by a passing unit test, source count, static 750 D1 country metadata rows or a build green check.

### Private same-event candidate grouping / review handoff (2026-10-10)

A new internal-only pure `scripts/lib/private-independent-event-review-queue.mjs` helper plus bounded manual CLI `scripts/ops/build-private-independent-event-review-queue.mjs` accepts **already privately acquired and structured** original-source candidate receipts (never raw customer uploads) and groups on the exact canonical event-claim SHA-256. It reuses the canonical 250-entity geography, category/event type authority and pinned originating organization registry. Each candidate must bind its originally published date, exact first-party HTTPS article URL and original article-content hash, and explicitly remain private/unlicensed/unpromoted. Same-origin article copies, syndicated material, forged publisher hosts and future/stale article clocks are rejected or not counted as independent. Two different original reporters + two different content hashes + publication time spread at most 90 minutes produces only `MULTI_ORIGIN_REVIEW_REQUIRED`, **never `commercial_event_admission`**.

The CLI reads private structured candidate JSON via bounded **stdin** and writes **sanitized numeric and claim-hash receipt JSON** to stdout, without the raw source headlines, article body, article URL, originating organization name, rights document, subject actors or internal event details. Input rejection prints only a generic safe error code and exits nonzero. It has **no cron, automatic signer, network access, model calls, Supabase/B2/D1 operations, x402 settlement or public website output**. Zero or one qualifying original source does not produce an approval; a mismatched canonical claim is NOT auto-merged through headline similarity. The human/authorized factual and legal reviewer must independently inspect genuine original article bytes, exact country/event nexus, syndication and derived commercial rights, then sign the complete private event package using the trusted Ed25519 review key. Only the existing `qualifyIndependentSameEvent` accepts those signed packages before any authorized B2→D1 Intelligence PUT.

**Unfinished production wiring:** the current ingestion feeds have not yet been independently demonstrated to emit the fully normalized private same-event claim receipts this CLI expects. A no-input dry-run or CI synthetic fixture is NOT current news, commercial rights proof or a launch-ready pipeline. Operator authorization of the real reviewer key, legal source rights and actual original event packages is required before automatic paid publication. No fake reviewer signature or artificial clock is permitted.

### Public intelligence freshness clock cannot be a storage clock (2026-10-10)

Verified historical derived intelligence is allowed to remain visible as **historical**, but the public `newest_at` and `current_within_24h` must be calculated from the **original publisher/event `published_at`**. A B2 write, restore, re-encryption, website deployment, CDN refresh, D1 checkpoint or ingestion `created_at` is NEVER evidence that the underlying original event happened today. Missing, future-dated or stale original publication time means the public 'current' freshness flag stays **false**, even when all three category rows have just been restored and their archive timestamps are recent. These protections apply to server B2 read, Cloudflare edge/browser failover and production website acceptance. They do **not** make unreviewed/one-source risk commercially eligible; the independent same-event reviewer signature, legal rights, signed GRO, B2 restore and D1 current-hot gates remain mandatory. No raw news, original source URL, publisher identity or private provenance may be emitted in x402 customer responses.

### Contradictory and retracted publisher evidence: commercial veto (2026-10-10)

A Dataminr-style early discovery objective is **not** proof that two articles confirm an event, nor is this claim to reproduce any competitor's proprietary system. Geomacro applies its existing WHO/WHAT/WHERE/WHEN structured same-event identity, original publisher source-native timestamp, exact registered originating organization, distinct private article SHA and independently reviewed derived-use rights. Existing private queue additionally requires each private original candidate to declare one independently audited `reporting_position`: `confirms`, `disputes` or `retracts`. Two confirmations from separate organizations do **not** override an identified genuine original correction or material dispute.

A reviewed exact-claim group with any `disputes` or `retracts` source is `MATERIAL_CONTRADICTION`, **not** `MULTI_ORIGIN_REVIEW_REQUIRED`. Same-byte contradictory dispositions fail before grouping. Even a review-queue success is NEVER source rights, a signed event, a publishable GRO or permission to charge. No RSS article, publisher name, URL, country/actor identity or internal provenance is written to the sanitized review queue.

Before the server-side legacy/authorized verified B2 Intelligence publication can pass `qualifyIndependentSameEvent`, the **Ed25519 signed reviewer package** must now contain `counterevidence_review`: `independent_counterevidence_review_completed=true`, a SHA256 private review receipt, trustworthy original-data `reviewed_at` within 90 minutes and after all confirming original publications, `sources_screened` at least the number of qualifying originals, exact `material_conflicts_detected` and `material_conflicts_resolved` accounting, `unresolved_material_conflicts=0`, and `retractions_detected=0`. Also every validating evidence member must explicitly affirm `reporting_position=confirms`. The complete signed receipt is bound into the trusted reviewer signature; unsigned booleans, missing reviewers, manipulated contradictory counts, stale clocks, or copied/retracted news fail closed. The count is an **attestation about the bounded reviewed scope**, NEVER proof no counterevidence exists across the entire internet.

This is a stricter publication gate, **not** automatic extraction/corroboration of every worldwide development. A real human or authorized trusted factual/legal reviewer and valid source-specific commercial derived-use rights are still required. Current public Intelligence/GRI/Risk Indices B2/D1 hot snapshots remain expired. x402 real funds cannot be accepted before genuine current qualified event packages, B2 GET/SHA/gzip readback, D1 current serving, no-charge acceptance and explicit founder ACK. Do not synthesize reviewer signatures or propagate publisher URLs/raw articles to x402 customers.

### Review signature binds exactly what the customer receives (2026-10-10)

The trusted independently signed event-review package must now include `reviewed_derived_row_sha256` for the **full, allowlisted, exact customer-facing Intelligence row**: `id,source_title,summary,category,severity,delta,created_at,published_at,public_status`. The publisher deterministically serializes those fields in fixed order and verifies SHA-256 **before Cloudflare authentication and any network PUT**. Extra source/raw/news/article/provider/URL properties, unsupported public narrative, non-integer severity, malformed timestamps, non-finite score movement or missing fields fail closed. Hashes of the original evidence only are insufficient: they would allow a downstream producer to alter the paid severity, cause/summary or public time while recycling an otherwise valid event-review signature.

Even if an authorized trusted reviewer signs a newly changed row, its customer `published_at` must equal either the signed event's native occurred-at clock or one of the signed genuine original publisher publication clocks and must remain within the six-hour original-current window. It can never advance to an ingestion, B2 upload, D1 restore, website publish or payment timestamp. Signing/hash commitments are derived-only and cannot leak private first-party article URLs or raw article content. Existing unsigned/legacy review packages without this full output-row commitment are intentionally **not backward compatible**: the commercial publisher rejects them; obtain a new authorized source-verified review package rather than bypassing this trust boundary.

This is a necessary security gate, **not** a claim that any real current article has now been sourced, licensed or corroborated. A reviewed row still requires distinct independent originals, counterevidence/retraction review, authorized Ed25519 signature, canonical risk/GRO proof, B2 readback, fresh D1 and x402 no-charge/owner approval. No real-money action is performed by these tests.

### Batch-level exact event deduplication (2026-10-10)

For one signed commercial Intelligence hot-snapshot publication, **each canonical
WHO/WHAT/WHERE/WHEN event identity and its SHA-256 event claim may appear at most
once**, regardless of distinct customer row IDs or multiple valid authorized
reviewer signatures. This prevents one reviewed development from being
represented as two separate paid event results, double-counted severity evidence
or duplicated x402 deliverables solely by changing the row identifier.
`qualifyIndependentSameEvent` rejects any second `same_event_claim_sha256`
in a batch **before any B2/D1 publication call**, with fail-closed
`INDEPENDENT_EVENT_DUPLICATE_CANONICAL_EVENT_CLAIM`. Valid separate events
with genuinely different canonical event identities are still independently
admitted, each requiring two distinct original reporting organizations, exact
source-native clocks, rights approval, signed reviewer package and exact
derived customer-row binding. This is **within-batch** duplicate protection,
not a claim of persistent cross-batch deduplication, live worldwide event
corroboration or authorization to collect USDC.
